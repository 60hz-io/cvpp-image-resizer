# RE100 인감 이미지 용량 줄이기

굿뉴스에너지 RE100 발전사업자가 전자계약 날인에 쓸 도장 사진을 **2MB보다 작게** 줄여 주는 웹 페이지입니다.
사진은 기기 안(브라우저)에서만 처리되고 서버로 전송되지 않습니다.

- 배포 주소: https://60hz-io.github.io/cvpp-image-resizer/
- 빌드 도구·서버 없음: `index.html` + `app.js` 두 파일로 동작하는 정적 페이지

## 사용자 흐름

1. **인감 확인 (온보딩)**: 발전사업자 서류로 제출한 인감증명서의 인감과 같은 도장을 써야 한다고 안내합니다. [네, 같은 도장을 사용하겠습니다]를 누르면 다음 화면으로 넘어갑니다.
2. **사진 선택**: ① 흰 종이에 도장 찍고 촬영 → ② [사진 선택하기] → ③ 저장 후 전자계약에 업로드 순서로 안내합니다. 데스크톱에서는 끌어다 놓기도 됩니다.
3. **처리**: 2MB 이하가 될 때까지 브라우저에서 압축합니다.
4. **완료·저장**: 플랫폼마다 저장 방식이 다릅니다 (아래 표).

### 플랫폼별 저장 방식

| 플랫폼 | 저장 방식 | 저장 위치 | 완료 알림 |
|---|---|---|---|
| Android | 처리가 끝나면 **자동 다운로드**. 버튼은 [다시 저장하기] | 갤러리 › Download 폴더 | 다운로드 요청 직후 "저장되었습니다" 모달 |
| iPhone·iPad | [사진에 저장하기] → 공유 시트 → '이미지 저장' | 사진 앱 | 공유 시트가 성공으로 끝나면 "저장되었습니다" 모달 |
| iOS에서 파일 공유를 지원하지 않는 환경 (iOS 15 미만, 기능을 막은 일부 앱 내 브라우저, HTTP 접속) | "사진을 길게 눌러 저장" 안내 | 사진 앱 | 없음 |
| 데스크톱 | [저장하기] → 다운로드 | 다운로드 폴더 | 없음 |

**알아 둘 제약**
- iOS 공유 시트는 사용자가 **어떤 항목**(이미지 저장, AirDrop, 파일에 저장 등)을 골랐는지 알려 주지 않습니다. 성공했는지만 알 수 있어서, 다른 항목을 골라도 "저장되었습니다"가 뜹니다. 사용자가 시트를 그냥 닫으면(`AbortError`) 아무것도 띄우지 않습니다.
- 웹페이지는 Android 다운로드가 실제로 끝났는지 알 수 없습니다. 그래서 다운로드를 요청한 직후 모달을 띄웁니다. 삼성 인터넷처럼 다운로드 확인 창을 먼저 띄우는 브라우저에서는 모달이 먼저 보일 수 있습니다.
- iOS 웹에서는 사진 앱에 자동 저장할 방법이 없습니다. 다운로드하면 '파일' 앱으로 들어가기 때문에 공유 시트를 씁니다.

## 이미지 처리 방식 (`app.js`)

| 항목 | 값·방식 | 이유 |
|---|---|---|
| 목표 용량 | `TARGET_BYTES = 1,800,000` 바이트 | 업로드 제한은 2MB입니다. OS에 따라 MB를 10⁶ 또는 2²⁰로 세므로 어느 쪽으로 봐도 안전한 값으로 잡았습니다 |
| 최대 픽셀 수 | `MAX_PIXELS = 16,000,000` | iOS Safari 캔버스 한도(16,777,216px)를 넘으면 `toBlob`이 `null`을 돌려줍니다 |
| 회전 | `createImageBitmap(..., { imageOrientation: 'from-image' })` | 휴대폰 사진의 EXIF 회전 정보를 픽셀에 반영합니다 |
| HEIC | Safari는 기본 지원으로 디코딩. 그 외 브라우저는 [heic2any](https://github.com/alexcorvi/heic2any)를 CDN에서 필요할 때만 불러옴 | 아이폰 기본 사진 형식 대응 |
| 출력 형식 | 투명 배경이 있으면 PNG, 없으면 JPEG(흰 배경) | 전자서명 서비스가 JPG·PNG만 받습니다 |
| 압축 | JPEG 화질 0.5~0.92 사이를 이진 탐색합니다. 그래도 넘치면 해상도를 줄이고 다시 탐색합니다(최대 12회) | 화질을 최대한 지키면서 목표 용량 맞추기 |
| 메모리 | 쓴 캔버스는 바로 `width = height = 0`으로 해제 | iOS는 캔버스 메모리가 쌓이면 탭이 종료됩니다 |

> 원본이 이미 2MB보다 작아도 다시 그려서 저장합니다. 그래서 용량이 조금 커질 수 있습니다(예: 298KB → 341KB). EXIF 회전 반영과 형식 통일을 위해 의도한 동작입니다.

## 파일 구성

```
index.html          화면 마크업 + 스타일 (라이트/다크 모드, 온보딩 인감 그림 SVG 포함)
app.js              디코딩·압축·저장·화면 전환 로직
assets/
  logo.png          굿뉴스에너지 로고 (다크 모드에서는 CSS filter로 반전)
  favicon*.png      파비콘 (라이트/다크)
  apple-touch-icon.png
  og-image.png      링크 공유 미리보기 (1200×630)
```

## 로컬에서 실행

```sh
python3 -m http.server 3000
# PC: http://localhost:3000
# 같은 Wi-Fi의 휴대폰: http://<PC의 내부 IP>:3000  (macOS: ipconfig getifaddr en0)
```

> **iPhone 저장 흐름은 HTTPS에서만 확인할 수 있습니다.** `navigator.share()`는 HTTPS 또는 `localhost`에서만 동작합니다. 휴대폰으로 `http://<내부 IP>`에 접속하면 공유 시트 대신 "길게 눌러 저장" 안내가 나옵니다. iPhone 흐름은 배포 주소에서 확인해 주십시오.

## 배포

GitHub Pages가 `main` 브랜치 루트(`/`)를 그대로 배포합니다. `main`에 push하면 1분 안팎으로 반영됩니다.

```sh
git push origin main
gh api repos/60hz-io/cvpp-image-resizer/pages/builds/latest --jq '.status'   # built 이면 완료
```

### ⚠️ `app.js`를 고쳤다면 버전 값을 올릴 것

`index.html` 맨 아래의 스크립트 주소에 버전이 붙어 있습니다.

```html
<script src="app.js?v=20261105b"></script>
```

GitHub Pages는 파일을 10분간 캐시합니다(`cache-control: max-age=600`). 버전을 올리지 않으면 **새 HTML과 이전 `app.js`가 섞여** 오류가 날 수 있습니다(예: `Cannot set properties of null`). `app.js`를 바꿀 때마다 `v` 값을 바꿔 주십시오.
